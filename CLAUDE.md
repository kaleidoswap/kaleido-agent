This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Project Is

KaleidoAgent is an autonomous Bitcoin L2 portfolio rebalancer for [KaleidoSwap](https://kaleidoswap.com). It uses Claude AI with MCP (Model Context Protocol) servers to maintain target allocations across BTC, USDT (RGB), and XAUT (RGB) on the Lightning Network, executing atomic HTLC swaps and managing Lightning channels via LSPS1.

## Commands

```bash
# Install
npm run install:all        # Install both agent + webapp deps

# Development
npm run dev:agent          # Run agent (tsx, file watching)
npm run dev:webapp         # Vite dev server on :5173
npm run dev:all            # Run both together

# Build
npm run build:agent        # tsc compile agent → /dist
npm run build:webapp       # Vite build webapp
npm run build:all          # Build both

# Run compiled agent
npm start

# Tests
npm test                   # Unit tests
npm run test:watch         # Watch mode
npm run test:integration   # Integration tests
npm run coverage           # v8 coverage report

# Run a single test file
npx vitest run tests/unit/scheduler.test.ts
```

The status server runs on `127.0.0.1:4242`. Check health with:
```bash
make health   # curl /health
make status   # curl /status (full state JSON)
```

## Architecture

**Nanobot is the core runtime.** It handles agent execution, scheduling (cron), MCP tool integration, Telegram messaging, and memory. Node.js provides a thin bridge API server for the webapp control panel.

### Execution Modes

- **skill** (default) — All agent work goes through Nanobot. Nanobot manages its own MCP connections. Scheduling via Nanobot cron (`nanobot-cron-sync.ts` writes `.nanobot/cron/jobs.json`).
- **mcp** (fallback) — Node.js connects MCP servers directly via `McpManager`. `AgentRunner` calls Claude API with 60+ tools. Only used when `agent.mode === "mcp"`.

### Boot Sequence (`index.ts`)

```
1. Load config → agent.config.json + .env
2. Ensure RLN node running
3. NanobotManager → validate → startGateway → syncCronJobs
4. WalletBridge (cli/agent/mcp based on config)
5. If mcp mode: connect McpManager
6. NanobotTaskRunner + NanobotChatRunner
7. Scheduler (manual triggers only)
8. BridgeServer on :4242
```

### Key Files

| File | Purpose |
|---|---|
| `index.ts` | Entry point; boots Nanobot, optional MCP, bridge server |
| `nanobot-manager.ts` | Nanobot lifecycle: config generation, gateway, skill sync, cron sync |
| `nanobot-task-runner.ts` | Runs tasks via `nanobot agent` CLI |
| `nanobot-chat-runner.ts` | Chat via `nanobot agent` CLI |
| `nanobot-cron-sync.ts` | Converts tasks.json → `.nanobot/cron/jobs.json` |
| `wallet-bridge.ts` | Wallet data via CLI, nanobot agent, or MCP |
| `scheduler.ts` | Manual task triggers only (no interval timers) |
| `status-server.ts` | Bridge API on :4242 for webapp |
| `agent-state.ts` | In-memory state: loop stats, portfolio, costs |
| `agent-runner.ts` | MCP mode fallback (direct Claude API turns) |
| `mcp-manager.ts` | MCP mode fallback (spawns MCP servers) |

### Nanobot Workspace (`.nanobot/`)

```
.nanobot/
├── config.json              # Generated by NanobotManager
├── cron/jobs.json           # Generated by nanobot-cron-sync.ts
└── workspace/
    ├── SOUL.md              # Agent identity
    ├── AGENTS.md            # Operating instructions
    ├── TOOLS.md             # Available tools
    ├── HEARTBEAT.md         # Health check tasks
    ├── skills/              # Synced from /skills
    ├── memory/              # Persistent memory

```

### Skills (`/skills`)

Markdown-based agent behaviors (SKILL.md + references/). 10 skills:
kaleidoagent, portfolio-manager, channel-manager, wallet-assistant, kaleidoswap, mpp, cross-l2, dca, node-manager.

### Webapp (`/webapp`)

React + Vite + Tailwind CSS. Control panel that polls `:4242/status` every 5s.
Tabs: Chat, Connect, Skills, Tasks. Sidebar: portfolio, wallet, recent runs.
No code changes needed when switching between skill/mcp modes — same API contract.

## Configuration

**`agent.config.json`** — primary config:
```json
{
  "agent": { "model": "claude-sonnet-4-6", "mode": "skill" },
  "mcp": { "kaleido": { "command": "kaleido-mcp", "args": [], "env": {...} } },
  "portfolio": { "targets": { "BTC": 70, "USDT": 20, "XAUT": 10 }, "dry_run": true, "trading_mode": "atomic" },
  "schedule": { "heartbeat_interval_sec": 300 },
  "nanobot": { "gateway_port": 18790, "heartbeat_interval_sec": 300, "wallet_fetch_method": "cli" },
  "skills": { "enabled": ["portfolio-manager", "channel-manager", "kaleidoswap", ...] }
}
```

**Wallet fetch methods** (`nanobot.wallet_fetch_method`):
- `cli` — shells out to `kaleido --json` (zero token cost)
- `agent` — calls `nanobot agent` with wallet prompt (costs tokens)
- `mcp` — uses McpManager directly (requires mcp mode)

## Swap Modes

- **atomic** — 5-step HTLC (fast, no deposit address needed)
- **rest** — deposit-based REST orders (fallback)
- **both** — try atomic first, fall back to REST

## Testing

Tests live in `/tests/unit/` and `/tests/integration/`. Vitest with `pool: 'forks'`. The unit tests mock MCP connections, provider calls, and tasksStore. Integration tests require real MCP servers.
