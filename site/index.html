How it works

Three Autonomous
Loops

The agent runs three continuous background loops — rebalancing your portfolio, keeping your Lightning node healthy, and generating daily reports. Beyond the loops, 9 skills cover DCA, cross-L2 moves, MPP payments, and an interactive wallet assistant. Claude AI reasons about every decision before acting.

Every 1 hour
Rebalance
Compares live portfolio against target allocations. If drift exceeds threshold, calculates the optimal swap and executes it atomically on Lightning.
  • Read live balances via WDK tools
  • Compute current vs. target allocations
  • Check risk limits before acting
  • Get live quote from KaleidoSwap
  • Execute atomic HTLC swap
  • Confirm settlement + log result
Every 5 minutes
Heartbeat
Monitors Lightning node health, flushes stuck RGB transfers, and auto-purchases channel liquidity via LSPS1 when outbound runs low.
  • Read node info + peer count
  • Audit channel inbound/outbound
  • Flush pending RGB transfer states
  • If outbound critical → LSPS1 channel buy
  • Pay bolt11 invoice from RLN wallet
  • Poll until CHANNEL_OPENING complete
Daily at 00:00 UTC
Summary
Generates a full portfolio snapshot — balances, trade history, market data, and performance report delivered via Telegram or log file.
  • Snapshot all asset balances
  • Retrieve full swap history
  • Fetch market prices + sentiment
  • Compute daily P&L vs. targets
  • Report via Telegram + log file

Atomic Swap Flow

Trustless HTLC
Settlement

No deposit address. No custodian. The agent coordinates the full 5-step HTLC swap across two MCP servers in a single tool-call sequence. Settles atomically on Lightning.

01
kaleidoswap_get_quote
→ rfq_id + raw amounts
Live quote for the pair to rebalance. Returns rfq_id (valid ~30s) with exact in/out amounts in raw asset units.
02
kaleidoswap_atomic_init
→ swapstring + payment_hash
Maker creates the HTLC. Returns encoded swapstring and the payment_hash the taker must lock funds against.
03
wdk_atomic_taker
→ whitelist HTLC on RLN
Agent calls the WDK RLN node to whitelist the incoming HTLC, then retrieves the node's pubkey for the maker to route to.
04
kaleidoswap_atomic_execute
→ HTLC settlement triggered
Maker executes against taker pubkey + payment secret. Both HTLCs settle simultaneously — atomic by construction.
05
kaleidoswap_atomic_status
→ poll → Succeeded
Agent polls until Succeeded. On success: sync asset state, log result. On failure: log reason, defer to next cycle.
Runtime Architecture

Two Execution
Modes

KaleidoAgent supports two modes set via agent.config.json. Nanobot mode (default) delegates to a detached gateway process — adding Telegram operator control, persistent cron scheduling, and resilience across restarts. MCP mode runs the LLM loop directly in-process for full token and tool-call observability.

# Process topology — MCP mode
 
kaleidoagent  node dist/index.js
├── kaleido-mcp  stdio child · WDK Spark + RLN + DEX + MPP (60+ tools)
├── StatusServer  :4242  /health /status /run /chat /config /tasks
├── Scheduler  fires tasks on interval or POST /run
└── AgentRunner  Anthropic SDK · full token + cost visibility
 
# External MCP servers (already running)
kaleidoswap-mcp  :3010 HTTP
wdk-wallet-rln-mcp  :3011 HTTP
mpp-gateway-mcp  :3012 HTTP
Data flow — task execution
1
Scheduler fires
Interval elapses or POST /run received. Loads SKILL.md for the task's skill, injects live state via !`cmd` shell expansions.
2
AgentRunner → Anthropic SDK
Builds system prompt from skill file. Calls Claude with the full allowed tool list. Tracks token usage and cumulative cost.
3
McpManager routes tool calls
Each tool_use block is dispatched to the correct MCP server (stdio or HTTP). Results appended to message history.
4
Loop until end_turn
LLM reasons, calls tools, observes results. Continues up to max_tool_calls_per_run (default 30).
5
RunResult → AgentState
Full trace (tool calls, final response, token cost) saved. Webapp sees it on next GET /status poll.
What you see in /status
·
tool_calls[]
Every tool name + input + result for the last run. Full reasoning trace.
·
usage.input_tokens / output_tokens
Per-run and cumulative token counts. Cost breakdown per model.
·
final_response
JSON output from the skill (action taken, amounts, drift %, result).
·
wallet_snapshot
BTC/USDT/XAUT balances captured after each run.

kaleidoagent  node dist/index.js

├── StatusServer  :4242
├── Scheduler → NanobotTaskRunner
│    spawn("nanobot agent -m <prompt>") → parse stdout JSON
└── NanobotManager.startGateway()
 
nanobot gateway  :18790  detached — survives kaleidoagent restart
├── reads .nanobot/config.json  (auto-generated)
├── reads .nanobot/workspace/skills/  (synced from skills/)
├── kaleido-mcp  own stdio child

├── kaleidoswap-mcp  :3010  wdk-wallet-rln-mcp  :3011  mpp-gateway-mcp  :3012
└── Telegram bot  users talk directly to Nanobot — bypasses kaleidoagent
Task execution — Nanobot mode
1
Scheduler fires
NanobotTaskRunner builds prompt with taskId, skillName, dry_run, portfolio params.
2
spawn("nanobot agent …")
Nanobot binary loads workspace/skills/<skill>/SKILL.md as system prompt. Uses its own MCP connections.
3
Nanobot reasons + acts
Black box to kaleidoagent. Nanobot calls tools, reasons, and produces a final response via stdout.
4
stdout parsed → RunResult
kaleidoagent parses JSON stdout. No tool call trace or token data — only the final output is visible.
5
Telegram users → direct
Telegram messages go straight to Nanobot gateway (:18790). kaleidoagent is not involved.
Skill sync pipeline
1
skills/ → .nanobot/workspace/skills/
NanobotManager copies all skill folders on gateway startup, skill toggle (PATCH /skills), and task edit.
2
!`cmd` → live state injection
Nanobot executes shell commands embedded in SKILL.md at load time — injects live balances, node info, etc. into the system prompt.
3
HEARTBEAT.md written
Task list snapshot written to workspace — Nanobot is aware of all scheduled tasks and their last run times.
4
npm run sync-skills
Manual sync command. Also: npm run validate checks all tool names resolve against the connected MCP servers.

## State  (injected at runtime)

!`kaleido --json spark balance`
!`kaleido --json rln balances`

## Logic

1. Read live balances from Spark + RLN via WDK tools
2. Convert all assets to USD at current market prices
3. Compute allocation % for BTC / USDT / XAUT
4. Find asset with largest deviation from target
5. If max_drift < rebalance_threshold_pct → SKIP
6. Apply risk checks (reserve, max_swap, stop_loss, orders)
7. kaleidoswap_get_quote → rfq_id
8. Execute 5-step atomic HTLC swap
9. Confirm settlement, sync asset state

Tech Stack

What's Inside

Reasoning
Claude AI
Anthropic Sonnet 4.6 via MCP tool calls. OpenAI GPT-4 supported as drop-in alternative.
Wallet SDK
WDK
Tether's Wallet Development Kit — Spark L2 + RLN Lightning. Extended with our own WalletManager and SwapProtocol npm packages.
DEX
KaleidoSwap
Lightning DEX for RGB assets. Atomic HTLC + REST orders + LSPS1. Integrated via kaleido-sdk in both WDK library and MCP layers.
Tool Protocol
MCP
Model Context Protocol. kaleido-mcp unifies 60+ tools (Spark, RLN, DEX, MPP) in one server. Standalone RLN + Spark MCP servers available separately.
Agent Runtime
Nanobot
Detached gateway process with Telegram operator surface, persistent cron scheduling, and SKILL.md system-prompt injection.
Assets
RGB
USDT and XAUT as RGB assets on Bitcoin Lightning. Native, sovereign, on-chain settlement without bridging to other chains.
Payments
MPP / L402
Machine Payments Protocol over HTTP 402. Agent pays for premium market data via Lightning micropayments — no API keys, no signup, pay-per-request.
Backend
TypeScript
Node.js 20 across all packages. Vitest unit + integration tests. Docker + Nginx for production. pnpm + npm workspaces.
Dashboard
React 18
Vite + Tailwind CSS. Real-time portfolio view, task scheduler, chat panel, and skills manager. Polls :4242/status every 5s.
