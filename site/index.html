01 Architecture

Three MCP servers.
One autonomous agent.

KaleidoAgent orchestrates three specialized MCP servers — each exposing domain-specific tools — through a central Claude AI reasoning loop. The agent decides when to act, what tools to call, and how to sequence multi-step flows.

02 Autonomous Loops

Three loops.
Zero human triggers.

The agent runs continuously. Each loop fires on its own schedule, executes a full Claude reasoning cycle with tool calls, and logs results to the status server. No webhooks, no manual triggers.

⚖️
Rebalance Loop
Every 5 minutes
Fetches live balances and derives USD values using KaleidoSwap as the price oracle. Computes allocation drift vs. configured targets (BTC 70% · USDT 20% · XAU₮ 10%). If drift exceeds the threshold, executes a swap — atomic HTLC first, REST fallback. Enforces stop-loss, max_swap_usd cap, and min BTC reserve on every run.
🩺
Heartbeat Loop
Every 5 minutes
Verifies RLN node is online, counts usable channels, totals outbound liquidity. Flushes pending RGB transfers and clears stuck orders. If outbound satoshis fall below min_outbound_liquidity_sat, autonomously purchases a new Lightning channel via LSPS1 — no human needed.
📊
Daily Summary
Every day at 00:00
Full portfolio snapshot at midnight: BTC + RGB balances, live exchange rates (BTC/USDT, XAU₮/USDT via KaleidoSwap quotes), total portfolio value in USD, current allocation percentages, session PnL, and complete trade history. Results stored in the status server and streamed to the webapp.
03 Swap Modes

Atomic HTLC by default.
REST fallback if needed.

The agent supports three trading modes, configurable per deployment. The preferred mode is atomic HTLC — a trustless, non-custodial swap that settles directly on Lightning with no deposit address required.

Atomic (HTLC)
Preferred · Trustless
5-step HTLC swap flow. No deposit address required. Assets move directly between Lightning channels via Hash Time-Locked Contracts. Fastest settlement, fully non-custodial, zero counterparty risk.
REST
Deposit-based
Classic deposit-based order flow. Agent creates an invoice or RGB address, places the order with KaleidoSwap, sends payment, then polls for fill. Used when outbound Lightning liquidity is insufficient for atomic.
Both
Smart Fallback
Attempts atomic HTLC first. If channel outbound liquidity falls below min_outbound_liquidity_sat, automatically falls back to REST. Combines reliability with trustlessness.
atomic swap flow — 6 steps
kaleidoswap_get_quote → rfq_id, from_asset.amount_raw, to_asset.amount_raw, from_asset.amount_display
kaleidoswap_atomic_init → swapstring, payment_hash — RFQ locked on maker side
wdk_atomic_taker → HTLC whitelisted on RLN node — taker ready to accept
wdk_get_node_info → taker_pubkey — passed to maker for HTLC routing
kaleidoswap_atomic_execute → HTLC settlement triggered by maker
kaleidoswap_atomic_status → Succeeded · poll until terminal state
04 LSPS1 Auto-Channel

Liquidity runs low.
Agent buys a channel.

When the heartbeat loop detects that outbound Lightning liquidity has dropped below the configured threshold, the agent autonomously purchases a new inbound channel from KaleidoSwap's LSP — all via LSPS1 protocol with a single Lightning payment.

Trigger condition total_outbound_sat < lsp.min_outbound_liquidity_sat
AND lsp.auto_buy_channel = true
lsp_balance_sat
Inbound liquidity the LSP will provide to the agent (e.g. 2,000,000 sats)
client_balance_sat
Initial outbound liquidity from client side (usually 0)
channel_expiry_blocks
Channel lifetime in blocks (4320 = ~30 days)
lsps1 channel purchase flow
wdk_get_node_info → client_pubkey (taker Lightning node)
wdk_connect_peer → connect to LSP node (pubkey@host:port)
kaleidoswap_lsp_estimate_fees → fee breakdown in sats
kaleidoswap_lsp_create_order → order_id, bolt11_invoice, order_total_sat
wdk_pay_invoice → Lightning payment sent to LSP
kaleidoswap_lsp_get_order → CHANNEL_OPENING → COMPLETED
05 Risk Controls

Guardrails at
every decision point.

Every rebalance run checks all risk parameters before executing any trade. Safe by default — dry_run=true unless explicitly overridden. No single failure cascades.

🔒
dry_run
Default ON. Agent describes what it would do but never places real orders. Set DRY_RUN=false to enable live trading. Checked before every swap.
💰
max_swap_usd
Hard cap per trade in USD. Swap amount is always clamped to this value regardless of portfolio size or drift magnitude.
⚡
min_btc_reserve_sats
Minimum Lightning BTC balance to preserve. Agent will never swap BTC below this floor — ensures node always has routing capacity.
📋
max_concurrent_orders
Agent checks open orders before placing a new one. If at the limit, skips this run entirely. Prevents position accumulation.
🛑
stop_loss_btc_sats
Emergency halt. If BTC balance drops below this threshold, all trading is suspended immediately. Hard floor, no exceptions.
📐
rebalance_threshold_pct
Minimum allocation drift to trigger a rebalance. Prevents overtrading on small fluctuations. Default 5% — only acts on meaningful deviation.
